# plan:0009 Task 4 — Canonicalization adapter + MRlap overlap correction

> **For agentic workers:** implementation companion to `plan:0009` Task 4.
> Steps use `- [ ]` checkboxes. Recommended executor:
> `superpowers:subagent-driven-development` (this increment is larger than

**Goal:** For each of the six eligible hormone strata, run the **MRlap
overlap-corrected** MR of germline hormone liability → long-COVID
(`GCST90454541`), fronted by a **hard-stop canonicalization adapter** that maps
each source family to MRlap-ready columns and injects the correct total `N`.
MRlap munges and runs cross-trait LDSC internally, returns the observed and
**overlap-corrected** causal effect, and we record the corrected effect beside
the Task-3 naive IVW — under the same **ancestry-flag / non-primary (KD1)** and
**bounded-sex (KD3)** ceilings, which overlap-correction does **not** lift.

**Design of record:** `entities/plans/0009-wave1-mr-hormone-pilot.md` (Task 4 +
Decision criteria). **Estimand:** `doc/plans/2026-07-03-wave1-gwas-mr-estimand.md`.
**Scale/overlap contract:** `plan:0008` KD2 + KD-scale; bounded-sex framing
`plan:0008` KD3. **Predecessor increments:**
`doc/plans/2026-07-04-plan0009-task2-hormone-instruments.md` (instruments) and
`doc/plans/2026-07-05-plan0009-task3-naive-mr.md` (naive comparator — the arm
this one is compared against).

**Architecture:** Extend the *isolated* `code/workflows/wave1-mr-hormone/`
Snakemake workflow — **not** the frozen `plan:0007` `wave1-mr/` run-of-record.
This is the one increment with a **genuinely new mechanism** (MRlap + its
internal GenomicSEM LDSC engine), so unlike Tasks 2–3 it does not reuse the
`plan:0007` estimator core. Four new scripts: (1) a **canonicalization adapter**
(`canonicalize_sumstats.py`) that reads each raw genome-wide harmonised sumstat,
maps its source-family columns to the MRlap canonical schema
(`rsid chr pos a1 a2 beta se N`), **injects the resolved total N**, and
**hard-stops** on any missing column or unresolved N; (2) a **setup rule**
(`setup_mrlap.R`) that installs MRlap + GenomicSEM at **pinned commits** into a
new `r-mrlap` conda env and hard-fails unless the resolved `GithubSHA1` matches;
(3) the **MRlap runner** (`run_mrlap.R`), one call per stratum × the shared
outcome, passing the raw canonical sumstats + the staged `eur_w_ld_chr` / HapMap3
references; (4) an **aggregator** (`aggregate_mrlap.py`) that joins the six MRlap
records with the Task-3 naive manifest into `mrlap_results.json`, placing the
overlap-corrected effect beside the naive IVW and stating the **instrument-set
non-identity** caveat.

**Tech stack:** Snakemake `--use-conda`; R 4.5 (`MRlap` + `GenomicSEM` — both
GitHub-only, no CRAN release — installed at pinned commits; `data.table`,
`lavaan`); Python 3.12 (`stdlib` `gzip`/`csv`; no pandas needed) for the
canonicalization adapter and aggregator (`stage.yaml` env). **No Python `ldsc`**
— MRlap's LDSC engine is GenomicSEM (pure R).

## Global constraints (from plan:0009 / plan:0008, binding)

- **Interpretation ceiling holds even after overlap correction.** Every estimate
  is **ancestry-flagged and non-primary** (KD1: outcome `GCST90454541` is the
  European-dominant ~85–90% multi-ancestry HGI broad/population meta; no EUR-only
  sibling) and any male-vs-female read is a **bounded exposure-architecture** probe
  (KD3), **not** a genotype×sex effect-modification test. **Correcting the UKB
  sample overlap does not lift either ceiling** — no MRlap result is reported as
  primary evidence for `hypothesis:0005` / `question:0007` / `question:0013`, nor
  as a sex-modification claim.
- **EUR LD reference vs multi-ancestry outcome — the correction inherits an
  outcome-side ancestry approximation.** MRlap runs cross-trait LDSC internally with
  the **EUR** `eur_w_ld_chr` reference. The Ruth exposures (European UKB) match it, but
  the **outcome** `GCST90454541` is European-dominant with ~10–15% non-European, and
  LDSC assumes the LD reference matches the GWAS sample — so the outcome h², single-trait
  intercept, and the **cross-trait intercept `int_crosstrait`** (the quantity that
  *drives* the overlap correction) are **ancestry-approximate**. This bites the
  correction *machinery*, not just interpretation, and is a distinct, mechanistic
  compounding of the KD1 flag. Every per-stratum + aggregate record carries
  `ldsc_ancestry_mismatch: true` with a one-line note; Task 5 states that the correction
  magnitude inherits this outcome-side ancestry approximation. (The **total-N = 1,100,445**
  injection is unaffected — it is the precision-N of the multi-ancestry meta betas.)
- **MRlap `N` is TOTAL, not effective.** For the binary outcome inject
  `N = cases + controls` (Σ per-ancestry `sample_size` from the `GCST90454541`
  `-meta.yaml` = **1,100,445**), **not** effective N; each Ruth stratum carries its
  continuous-trait sample size (pinned from the GWAS Catalog study record). The
  adapter **hard-stops** if N is unresolved.
- **Naive↔MRlap instrument-set non-identity.** MRlap selects instruments by its own
  genome-wide **distance pruning** (`MR_pruning_dist` / `MR_pruning_LD`), which is
  **not** the naive arm's 1000G-EUR LD-clump (r² < 0.001, 10 Mb). The naive↔corrected
  delta therefore conflates the overlap correction with an instrument-set difference —
  it is **not pure overlap bias**. This must be stated wherever the two are shown together.
- **Different SCALE *and* different instrument set — naive↔corrected is sign/direction
  only.** MRlap **standardizes** internally (`std_beta = Z/√N`; `run_MR` operates on the
  standardized effects), so `corrected_effect` is a **standardized effect
  (SD-outcome-liability per 1-SD exposure)** — **NOT** log-OR/SD, and **no
  `or = exp(b)`** may be computed for it. The naive IVW is log-OR long-COVID per 1-SD
  hormone. So naive↔corrected differ in **both scale and instrument set** → compare
  **sign/direction**, never OR-scale magnitude. The **one clean, like-for-like delta**
  is MRlap **observed → corrected** (same distance-pruned set, same standardized scale)
  — that delta *is* the overlap(+winner's-curse) correction. Label the scale on every
  estimate: naive = `log-OR/SD`, MRlap observed & corrected = `MRlap standardized (SD/SD)`.
- **Two exposure-side caveats carried into interpretation.** SHBG and total
  testosterone are **not independent** (shared Ruth loci; steroid-axis pleiotropy);
  and the **female-testosterone stratum is weakest-instrumented yet most
  decision-relevant** — a wide/weak corrected estimate is informative, not a failure.
- **Weak is informative; technical faults hard-stop.** A wide or weak corrected
  estimate (esp. female testosterone) is a valid scientific outcome. MRlap failing to
  run, failing to reconcile scales/references, or returning a non-finite corrected
  effect from a well-instrumented stratum is a **technical fault** → hard-stop and repair.
- **Reproducibility.** MRlap **and** GenomicSEM commits pinned and asserted at setup;
  MR pruning/threshold params pinned in `config.yaml`; no Python-`ldsc` in the lock
  set. Payloads/outputs stay **off Dropbox** under `data/` + `results/` (gitignored,
  symlinked to `/data`); `git status` shows nothing under `data/`.

## canonicalize_sumstats.py — the hard-stop adapter

`--config <cfg> --source-family <ruth-exposure|hgi-outcome> --stratum <name|"outcome">
--in <raw.h.tsv.gz> --out <canonical.tsv.gz>`. Streams the gz line-by-line
(stdlib `gzip` + `csv`; no full load), maps the source-family columns to the
canonical schema, injects the resolved total N, writes a lean 8-column gz
(`rsid chr pos a1 a2 beta se N`) — dropping the ~15 unused columns.

```python
RUTH_MAP = {   # hm_-prefixed GWAS-Catalog harmonised SSF (Ruth continuous traits)
  "rsid": "hm_rsid", "chr": "hm_chrom", "pos": "hm_pos",
  "a1": "hm_effect_allele", "a2": "hm_other_allele",   # a1 = effect allele (beta's ref)
  "beta": "hm_beta", "se": "standard_error"}           # SE is flip-invariant; non-hm col is correct
HGI_MAP = {    # non-hm GWAS-Catalog harmonised SSF (HGI long-COVID outcome)
  "rsid": "rsid", "chr": "chromosome", "pos": "base_pair_location",
  "a1": "effect_allele", "a2": "other_allele",
  "beta": "beta", "se": "standard_error"}
```

**Hard-stops (all loud, non-zero exit):**
1. **Missing column** — any mapped source column absent from the raw header →
   `stop`, naming the missing column and the source family.
2. **Unresolved N** — resolve N from the config (`exposures[stratum].n` for a Ruth
   exposure; `outcome.total_n` for the outcome). If absent, non-integer, or ≤ 0 →
   `stop`. N is written as a constant column on every row.
3. **Empty output** — if 0 data rows survive (after dropping rows with a missing
   `rsid`/`beta`/`se`, whose count is logged) → `stop` (a canonical file with no
   usable rows is a fault, not a quiet empty artifact).

The adapter does **not** do row-level QC beyond dropping unusable rows — MRlap
munges (strand/allele/NA handling) internally. It writes a small sidecar
`{out}.canonical.json`: `{source_family, stratum, n_injected, n_rows_in,
n_rows_out, n_dropped, columns_mapped}` for provenance.

## setup_mrlap.R — pinned-commit install + assert (mirrors setup_twosamplemr.R)

`--config <cfg> --sentinel <path>`. In the `r-mrlap` conda env, install in
dependency order: **TwoSampleMR @ pinned tag** (the transitive engine MRlap calls;
`remotes::install_github(cfg$mrlap_env$twosamplemr_repo, ref = <twosamplemr_ref>,
upgrade = "never")` — pulls `ieugwasr` from CRAN), then **GenomicSEM @ pinned
commit**, then **MRlap @ pinned commit**. Then **assert** both the GitHub commits
**and** the TwoSampleMR/ieugwasr package versions:

```r
for (pkg in c("GenomicSEM", "MRlap")) {                       # commit-SHA assert
  sha  <- utils::packageDescription(pkg)$GithubSHA1
  want <- if (pkg == "MRlap") cfg$mrlap_env$mrlap_ref else cfg$mrlap_env$genomicsem_ref
  if (is.null(sha) || substr(sha, 1, 40) != substr(want, 1, 40))
    stop(sprintf("setup_mrlap: %s GithubSHA1 %s != pinned %s — HALT", pkg, sha, want))
}
for (pv in list(c("TwoSampleMR", cfg$mrlap_env$twosamplemr_version_expected),
                c("ieugwasr",   cfg$mrlap_env$ieugwasr_version_expected))) {   # version assert
  got <- as.character(utils::packageVersion(pv[[1]]))
  if (got != pv[[2]])
    stop(sprintf("setup_mrlap: %s %s != pinned %s — HALT", pv[[1]], got, pv[[2]]))
}
```

Write the sentinel `.setup_mrlap.json`: `{mrlap_sha, genomicsem_sha,
twosamplemr_version, ieugwasr_version, r_version, sessionInfo_pkgs,
installed_at_note}` (mirrors the `setup_twosamplemr` sentinel shape, plus the
transitive-engine versions). The `r-mrlap` env first-build (r-base v4.5 + lavaan +
compiled deps + three GitHub/CRAN source installs) is ~15–20 min — expected, one-time.

## run_mrlap.R — the MRlap call + hard-stop (one per stratum)

`--config <cfg> --stratum <name> --exposure <canonical.tsv.gz>
--outcome <canonical.tsv.gz> --results-out <json> --dump-out <rds>`. Resolves
`trait`/`sex` from `config$exposures` by `--stratum` (the `build_instrument.R`
pattern). Reads both canonical sumstats with `data.table::fread`. **MRlap writes
temp files named from `exposure_name`/`outcome_name` into the process CWD** — the
shared `outcome_name` would collide across strata under any `-c>1` run — so
`setwd()` into a **stratum-specific temp dir** before the call and restore CWD
after (correctness no longer depends on `-c1`):

```r
work <- file.path(tempdir(), paste0("mrlap_", wildcards_stratum)); dir.create(work, recursive = TRUE)
old <- setwd(work); on.exit(setwd(old), add = TRUE)             # isolate MRlap's CWD temp files
res <- MRlap::MRlap(
  exposure = as.data.frame(exp_dt), outcome = as.data.frame(out_dt),
  exposure_name = spec$name, outcome_name = cfg$outcome$name,
  ld  = cfg$mrlap$ld, hm3 = cfg$mrlap$hm3,
  MR_threshold   = as.numeric(cfg$mrlap$MR_threshold),
  MR_pruning_dist = as.numeric(cfg$mrlap$MR_pruning_dist),
  MR_pruning_LD   = as.numeric(cfg$mrlap$MR_pruning_LD),
  MR_reverse      = as.numeric(cfg$mrlap$MR_reverse),
  save_logfiles = FALSE, verbose = TRUE)
saveRDS(res, dump_out)          # full return preserved (provenance; nothing silently dropped)
```

**Extract + record** (field names confirmed against the pinned MRlap source —
these are exact, not to-be-guessed):

- from `res$MRcorrection`: `observed_effect` (± `observed_effect_se`, `_p`) —
  MRlap's own uncorrected estimate on its distance-pruned set; `corrected_effect`
  (± `corrected_effect_se`, `_p`) — **the overlap-corrected estimate**;
  `test_difference` / `p_difference`; `m_IVs`. Both effects are **MRlap-standardized
  (SD/SD)** — record `"scale": "MRlap standardized (SD-outcome per 1-SD exposure)"`
  and do **NOT** compute `or = exp(b)` for either (that scale is not a log-OR).
- from `res$LDSC`: `h2_exp`, `h2_out` (± se), `int_exp`, `int_out` (single-trait
  intercepts), `gcov` (genetic covariance), **`int_crosstrait`** (± `int_crosstrait_se`)
  — the **cross-trait LDSC intercept**, the quantity that encodes the UKB sample
  overlap and drives the correction — plus `rg`.
- the **pruned-SNP exposure/outcome association dataframe** this pinned build returns
  (record its rsID set / count) — materialises the naive↔MRlap instrument-set non-identity.

**LDSC-plausibility floor (non-gating `quality_flags`).** The hard-stop below catches
*non-finite* corrected estimates, but a **degenerate / ill-converged LDSC fit** — `h2_exp`
or `h2_out ≤ 0`, `abs(rg) > 1`, or an implausibly large `int_crosstrait` — can produce a
*finite-but-garbage* correction that would otherwise pass silently ("green but wrong").
So record a **non-gating** `quality_flags` array on the LDSC block: raise
`ldsc_h2_nonpositive` when `h2_exp <= 0 || h2_out <= 0`, `ldsc_rg_out_of_bounds` when
`abs(rg) > 1`, and `ldsc_crosstrait_intercept_implausible` when
`abs(int_crosstrait) > 1` (or MRlap emits a low-h²/convergence warning). This is a **flag,
not a gate** — it mirrors Task 2's `below_target_n` / Task 3's `high_harmonisation_dropout`
pattern, surfacing a degenerate fit *beside* the number rather than propagating it into a
hard-stop or silently trusting it. A raised flag does **not** stop the run; it is carried
to the aggregate and read at Step 11.

**IV floor (informative, mirrors the naive 3-instrument floor):** if
`m_IVs < cfg$instrument$min_instruments_mr` (= 3), write the record with
`status: "insufficient-mrlap-ivs"` and the observed/corrected values MRlap
returned, but **do not** treat it as a quotable corrected result — a 1–2-IV
correction is recorded, not reported. (Won't trigger for the six built strata —
all ≥159 instruments per the task:t089 Task-2 sidecars — but honours "weak is informative".)

**Determinism.** MRlap's corrected-effect **SE and covariance are estimated by a
Monte-Carlo sampling strategy** (`get_correction` runs thousands of simulations — the
first real fit under task:t089 reported "17000 simulations were used to estimate the variance and the
covariance"), **not** analytically — so the fit **is stochastic**. The runner therefore
`set.seed()`s from a config-pinned seed (`mrlap.seed = 20260705`) **before** the MRlap
call and records the seed in the per-stratum JSON. Step 11 includes a run-twice-identical
spot-check on one stratum to confirm the corrected effect + SE reproduce bit-for-bit under
the fixed seed. *(An earlier draft wrongly assumed an analytic, seed-free SE.)*

**Hard-stop (technical fault, mirrors Task 3):** after MRlap returns, if the
load-bearing fields cannot be located, or `corrected_effect`/`observed_effect`/
their SEs/p are non-finite, or `m_IVs` is absent/0 (MRlap produced no estimate),
`stop(...)` naming the stratum. A wide/weak *finite* corrected estimate is **not**
a fault — record it (`status: "corrected"`).

## aggregate_mrlap.py → mrlap_results.json

`--config <cfg> --results <6 jsons> --naive <naive_mr_results.json>
--benchmarks <6 tsv> --setup <.setup_mrlap.json> --manifest <out>`. Joins the six
MRlap records with the Task-3 naive manifest (aligning by `stratum`), **hard-stops**
on any missing/malformed input **and** on any `status: "corrected"` record with a
non-finite `corrected_effect`/`se`/`pval` (defense-in-depth re-assert of the
runner's gate). A `status: "insufficient-mrlap-ivs"` record is **carried, not
hard-stopped** (counted in `summary.n_insufficient_ivs`, its values flagged
non-quotable).

**Naive-IVW extraction path (exact, hard-stop).** Task-3's per-stratum naive record
stores methods as a list: `methods: [{method: "Inverse variance weighted", b, se, pval,
or, nsnp}, {method: "MR Egger", ...}, {method: "Weighted median", ...}]`. The aggregator
pulls the IVW row by **exact match** `method == "Inverse variance weighted"` and reads
`{b, se, pval, or, nsnp}` from that entry (`nsnp` = the IVW instrument count, the naive
side of the instrument-set non-identity). If the IVW entry is **absent or renamed** for
any stratum, **hard-stop** naming the stratum — the join fails loud rather than silently
emitting a null `naive_ivw` column.

  non-identity** stated (`comparison_note`): naive = `log-OR/SD` (1000G-clumped),

  MRlap **observed→corrected** (same set, same std scale).
- **Reproducibility:** MRlap **and** GenomicSEM `GithubSHA1` **and** the transitive
  `TwoSampleMR`/`ieugwasr` `packageVersion`s pinned and asserted at setup

  Python `ldsc`** in the lock set.

  KD1/KD3 ceilings still bind after overlap correction; the `cross_stratum` block is a
  descriptive corrected-sign read, not a sex-modification test.

  multi-ancestry outcome → outcome-side ancestry-approximate `int_crosstrait`); and each
  LDSC block carries non-gating `quality_flags` (`ldsc_h2_nonpositive` /
  `ldsc_rg_out_of_bounds` / `ldsc_crosstrait_intercept_implausible`) so a degenerate

genuinely new mechanism** (MRlap + its GenomicSEM LDSC engine, on a new pinned
